01. Task Definition

The goal of this project is to train a simulated robot arm to open a door entirely through reinforcement learning — no hand-coded motion planning or trajectory optimization. The robot must discover on its own how to reach for the door handle, close its gripper, rotate the latch, and pull the door open. Below we describe the specific environment setup and what makes this task non-trivial for an RL agent.

Environment

  • Simulator: MuJoCo (via robosuite v1.5)
  • Robot: Franka Emika Panda — 7-DoF arm with parallel-jaw gripper
  • Task: Door — reach the handle, grasp it, rotate the latch, and pull the door open
  • Observations: Low-dimensional state (joint positions, velocities, gripper state, door hinge angle, handle position) — 39-dim vector
  • Actions: 8-dim continuous (7 joint velocities + 1 gripper open/close)
  • Horizon: 500 timesteps per episode

Why This Task Is Challenging

The agent must discover a sequence of coordinated behaviors through trial and error:

02. Reward Design

In reinforcement learning, the reward function is the only signal the agent receives about whether it is doing well or poorly. A poorly designed reward can cause the agent to learn unintended behaviors (reward hacking) or fail to learn at all. For a sequential task like door opening, the reward must provide a gradient that guides the agent through each phase — reaching, grasping, rotating, and pulling — without rewarding any single phase so much that the agent stops progressing.

Baseline Reward (robosuite default)

The robosuite Door environment includes a built-in shaped reward with three components. These provide a reasonable starting point, but as we discovered, they have a critical blind spot:

0 – 0.25
Reaching
→
0 – 0.25
Rotating
→
1.0
Door Open
  • Reaching: 0.25 × (1 − tanh(10 × dist)) — smooth gradient toward the handle
  • Rotating: Proportional to handle rotation angle (locked door variant)
  • Completion: Sparse +1.0 when the door is fully open

Our Custom Additions (Wrapper Shaping)

After analyzing the baseline reward, we identified a critical gap: there is no reward signal for grasping. The reaching reward maxes out at 0.25 when the gripper is near the handle, and the rotating reward only activates once the handle is already turning — but the agent receives zero feedback for the act of closing its fingers around the handle. This means the agent must randomly discover that gripping leads to handle rotation, which is a difficult exploration problem. To address this, we added three shaping terms in our Gymnasium wrapper, layered on top of the base reward without modifying robosuite’s source code:

+0.25
Grasp Reward
−0.01·||a||²
Action Penalty
−0.002
Time Penalty
  • Grasp reward (+0.25): Detects gripper contact with handle geoms via _check_grasp(). Bridges the reaching → rotating gap.
  • Action penalty: Discourages large/jerky joint commands, producing smoother motion and reducing episode-to-episode variance.
  • Time penalty: Small per-step cost that prevents the agent from hovering near the handle indefinitely.

SAC Training Diagnostics

Beyond the reward curve, we monitor SAC’s internal training signals to verify that learning is proceeding correctly. The critic loss measures how accurately the value network predicts future rewards — it should decrease and stabilize as training progresses. The actor loss reflects how well the policy maximizes the critic’s Q-values. The entropy coefficient is automatically tuned by SAC: it starts high (encouraging exploration) and decreases as the policy becomes more confident in its actions. 06. Method Details

We chose Soft Actor-Critic (SAC) as our RL algorithm after considering several alternatives. PPO is the most commonly used algorithm in RL research, but SAC is generally preferred for continuous control tasks with expensive simulation steps because of its superior sample efficiency. Below we describe the algorithm, our hyperparameter choices, and the software stack that ties everything together.

Why SAC?

Soft Actor-Critic (SAC) is an off-policy actor-critic algorithm that maximizes both expected reward and entropy. It maintains a replay buffer of past transitions and learns from them repeatedly, making it significantly more sample-efficient than on-policy methods like PPO which discard data after each update.

  • Sample-efficient — learns from a replay buffer, reusing past experience (critical when each environment step is expensive)
  • Entropy regularization — encourages exploration, preventing the policy from collapsing to a single strategy too early
  • Continuous actions — natively handles the 8-dim continuous action space (7 joints + gripper)
  • Auto-tuned entropy — the entropy coefficient adjusts automatically during training (visible in the diagnostics plot above)

07. Discussion & Reflections

This section reflects on the key takeaways from the project: what design decisions had the most impact, where the current approach falls short, and what directions could improve performance in future work.

What Worked

  • SAC's entropy regularization was critical for exploration in the early stages — without it, the agent would converge to a poor local minimum
  • Reward shaping provided a smooth gradient that guided the agent through the reach → grasp → rotate sequence
  • The custom grasp reward was the single highest-impact change — it filled a critical gap in the learning signal between "hand near handle" and "handle rotating"
  • Training on CPU (MacBook Pro, 32 GB) completed in ~40 minutes for 200k steps — no GPU required for this task

Limitations

  • High variance across episodes (reward ranges from 26 to 453) — the policy is sensitive to initial door position randomization
  • All episodes run for the full 500-step horizon — the agent never "finishes early," suggesting the time penalty may need tuning
  • Training uses low-dimensional state observations — real-world deployment would require vision-based policies
  • Reward engineering required task-specific knowledge about the grasp mechanics

Future Work

  • Train with the improved reward (grasp + action penalty + time penalty) and compare against baseline
  • Train with image observations to move toward sim-to-real transfer
  • Apply the same pipeline to harder tasks (block stacking, nut assembly)
  • Compare SAC vs PPO performance on this task
  • Experiment with curriculum learning — gradually increase the randomization range
